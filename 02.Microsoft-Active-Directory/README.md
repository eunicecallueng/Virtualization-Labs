## 🖥️ On-Premises Active Directory Configuration & Lab Journey

In this lab, I built an enterprise-grade Active Directory environment from scratch—setting up core network infrastructure, designing a clean OU structure, provisioning user identities, and enforcing security GPOs.

### 📚 Hands-on Exercises
| # | Exercise & What I Built 🛠️ | Real-Life Enterprise Best Practice 💡 | Demo / Media |
|---|---|---|---|
| **01** | **AD DS Installation & DC Promotion**<br>Promoted my first Windows Server to a Primary Domain Controller for `nycehomelab.local`. | **High Availability & DNS Naming:** Production environments deploy at least two DCs for redundancy and use routable split-brain DNS domain names (e.g., `ad.company.com`) instead of `.local` domains for cleaner cloud integration. | [Read details](https://github.com/eunicecallueng/Virtualization-Labs/blob/main/02.Microsoft-Active-Directory/Configuring%20Active%20Directory/README.md)
| **02** | **DNS & Network Services Setup**<br>Configured Active Directory-Integrated Forward and Reverse Lookup zones for local name resolution. | **AD-Integrated Replication:** Always store DNS zones inside Active Directory so DNS data automatically replicates across all DCs securely over encrypted AD protocols. | [Watch Demo](./media/02-dns-config.gif) |
| **03** | **DHCP Server Deployment**<br>Authorized a DHCP server and created dynamic IP scopes with options for DNS and Default Gateway. | **DHCP Failover:** Run DHCP in a High Availability (HA) split-scope or Failover mode (Hot Standby/Load Balance) across separate servers to eliminate single points of failure. | [Watch Demo](./media/03-dhcp-setup.gif) |
| **04** | **OU Architecture Design**<br>Built structured top-level OUs (`Nyce_Users` vs. `Workstations`) instead of leaving accounts in default containers. | **Avoid Default Containers:** Never link Group Policies directly to default `Users` or `Computers` containers. Custom OUs give you precise control over policy inheritance and permissions. | [Watch Demo](./media/04-ou-design.gif) |
| **05** | **Departmental Sub-OU Segmentation**<br>Segmented users into departmental sub-OUs (`BPO_Roles`, `HR_Department`, `IT_Department`, `Unactive_Employees`). | **Targeted Scoping & Offboarding:** Mirroring business departments in sub-OUs simplifies Entra Connect filtering (cloud sync) and allows targeted software/policy deployments per team. | [Watch Demo](./media/05-sub-ous.gif) |
| **06** | **User Account Provisioning**<br>Provisioned standardized user accounts (e.g., `jordan.reed`), standardizing UPNs and core contact attributes. | **Standardized Schema:** Consistently populate UPNs, employee IDs, and job titles during onboarding to streamline Single Sign-On (SSO) and automated HR system integrations. | [Watch Demo](./media/06-user-provision.gif) |
| **07** | **Security Groups & RBAC**<br>Created Global and Domain Local security groups to implement Role-Based Access Control. | **AGDLP Strategy:** Always follow the AGDLP principle (Accounts → Global Groups → Domain Local Groups → Permissions) rather than assigning direct permissions to individual user accounts. | [Watch Demo](./media/07-rbac-groups.gif) |
| **08** | **Workstation Domain Joining**<br>Joined Windows client VMs to the domain and placed them into the managed `Workstations` OU. | **Automated Staging:** Pre-stage computer accounts in their target OU before joining, or use deployment tools (Autopilot / MDT) so endpoint security policies apply immediately upon boot. | [Watch Demo](./media/08-domain-join.gif) |
| **09** | **Domain Password & Lockout Policy**<br>Enforced baseline password complexity, history limits, and lockout thresholds across the domain via `gpmc.msc`. | **NIST Compliance:** Modern enterprise guidelines recommend a minimum 12 to 14-character length, moderate lockout thresholds (e.g., 5–10 attempts), and cloud Smart Lockout to protect against external brute-force attacks. | [Watch Demo](./media/09-password-policy.gif) |
| **10** | **Fine-Grained Password Policies (FGPP)**<br>Configured Password Settings Objects (PSOs) to enforce stricter password requirements (16+ chars) for IT staff. | **Tiered Privileges:** Apply stricter password lengths and shorter session lifespans on privileged IT accounts without burdening regular end-users with unrealistic password requirements. | [Watch Demo](./media/10-fgpp-pso.gif) |
| **11** | **GPO: Network Drive Mapping**<br>Automated drive mappings (`Company_Data`) upon login using Group Policy Preferences. | **Item-Level Targeting (ILT):** Use Group Policy Preferences with ILT scoped to security groups instead of legacy logon batch scripts (`.bat` / `.vbs`) for faster, more reliable logins. | [Watch Demo](./media/11-drive-mapping.gif) |
| **12** | **GPO: Control Panel Restriction**<br>Restricted non-administrative users from opening Control Panel and system settings applets. | **Principle of Least Privilege:** Standard users should never have access to system settings or administrative tools, preventing accidental or malicious machine misconfiguration. | [Watch Demo](./media/12-prohibit-cp.gif) |
| **13** | **GPO: USB Storage Blocking**<br>Blocked unauthorized USB removable storage read/write access across managed workstations. | **Data Loss Prevention (DLP):** Restricting removable media mitigates data exfiltration and prevents malware infections (e.g., rogue USB drives), with security group exemptions for approved personnel. | [Watch Demo](./media/13-usb-block.gif) |
| **14** | **GPO: User Account Control (UAC)**<br>Configured UAC to mandate secure desktop credential prompts whenever administrative elevation occurs. | **Zero Trust Endpoints:** Always enforce UAC on secure desktop prompts. Standard users should never hold local administrator rights on corporate workstations. | [Watch Demo](./media/14-enforce-uac.gif) |
| **15** | **GPO: Inactivity Screen Lock**<br>Enforced an automated 15-minute screen lock timeout requiring password re-entry on idle sessions. | **Compliance & Walkaway Security:** Idle lockouts (typically 10–15 minutes) are mandatory under CIS benchmarks, ISO 27001, and SOC2 standards to protect unattended laptops in open offices. | [Watch Demo](./media/15-screen-lock.gif) |
| **16** | **GPO: WSUS Patch Management**<br>Configured Windows Update policy settings to route client endpoint patching through an internal WSUS server. | **Staged Deployment Rings:** Deploy software patches in phased rings (e.g., IT Test Group → Pilot Group → General Production) to verify system stability before rolling updates enterprise-wide. | [Watch Demo](./media/16-wsus-update.gif) |
